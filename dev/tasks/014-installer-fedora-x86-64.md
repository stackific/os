## Ask

```text title="Prompt" wrap
Bring the installer to the Fedora 45 x86_64 live ISO, so it installs Stackific OS into a drive's free space or onto a whole drive, as on Arch x86_64, and the installed system starts from Limine on our own 4 GiB FAT32 ESP. Reuse the one installer crate: add a Fedora implementation of its Base trait and an RPM, stackific-installer, built with mock. Kernel updates keep Limine's menu current through Fedora's own kernel-install and dracut, with one small kernel-install plugin of ours (Limine reads no Boot Loader Spec entries, and no Limine helper is packaged for Fedora); Limine comes from Terra. ```
```

## Goal
The Fedora x86_64 live ISO installs Stackific OS in both modes from the launcher or the boot menu, and the installed system starts through the firmware's "Stackific OS" entry and Limine, reaches its login screen with SELinux enforcing, and keeps Limine's menu current when dnf5 installs or removes a kernel. `just fedora test-install` proves it.

Upstream facts (checked 2026-11-07):
- **The live image at runtime.** `flags="dmsquash"` makes kiwi build with dracut's `dmsquash-live` (not `kiwi-live`) (https://github.com/OSInside/kiwi/blob/v11.1.1/kiwi/defaults.py#L1808-L1826). dmsquash-live mounts the ISO at `/run/initramfs/live`, links the boot device at `/run/initramfs/livedev`, and bind-mounts the root image at `/run/rootfsbase`, the lower layer of the overlay `/` (https://github.com/dracut-ng/dracut-ng/blob/111/modules.d/70dmsquash-live/dmsquash-live-root.sh L93, L113-131, L425-430; `modules.d/70overlayfs/mount-overlayfs.sh` L18-20). So `live_root` is `/run/rootfsbase` and `live_medium` `/run/initramfs/live`.
- **What kiwi leaves in the live root.** It deletes its `/etc/dracut.conf.d/02-livecd.conf` after building the initrd, moves the initrd onto the ISO (the root has none), and empties `/etc/machine-id` (kiwi v11.1.1 `kiwi/builder/live.py` L478-484, L581-586; `kiwi/system/setup.py` L320-347). `dmsquash-live` refuses hostonly builds and is included only on request, so a normal dracut run on the target leaves it out (`modules.d/70dmsquash-live/module-setup.sh` at dracut-ng 111).
- **Versions in Fedora 45:** kiwi 11.1.1, dracut 111-5.fc45, systemd 262.1-1.fc45, kernel 7.2.15-300.fc45, dnf5 5.4.6.0, efibootmgr 18-13.fc45, GNOME 51.0, glib2 2.90.0 (https://bodhi.fedoraproject.org, https://mdapi.fedoraproject.org/f45/pkg/<name>).
- **Limine in Terra 45:** `limine-12.9.6-1.fc45` (x86_64, aarch64; BSD-2-Clause; requires glibc): `/usr/bin/limine`, `/usr/share/limine/BOOTX64.EFI` (and `BOOTAA64.EFI`), no kernel-install plugin, no scripts (https://repos.fyralabs.com/terra45/repodata/; spec https://github.com/terrapkg/packages/blob/9bde6cab470dd4b17fab8928f0f827b222b75059/anda/system/limine/limine.spec). Neither Fedora 45 nor Terra 45 has `limine-entry-tool`, `limine-snapper-sync` or any Limine kernel-install plugin (mdapi; Terra's metadata). Limine 12.9.6 reads only `limine.conf` (no Boot Loader Spec entries) and only FAT and ISO9660 (https://github.com/Limine-Bootloader/Limine/blob/v12.9.6/CONFIG.md, README.md).
- **kernel-install (systemd 262):** config from the first of `/etc/kernel/install.conf`, `/run/…`, `/usr/local/lib/…`, `/usr/lib/kernel/install.conf`, extended by `install.conf.d/*.conf` drop-ins; environment variables win. `$BOOT` is the first of `/efi`, `/boot`, `/boot/efi` holding `loader/entries/` or `<entry token>/`, unless `BOOT_ROOT=` is set. `layout=auto` picks `bls` only when `$BOOT/loader/entries.srel` says `type1` or `$BOOT/<entry token>` exists, else `other`; with `other`, kernel-install itself installs nothing. Without a machine ID, kernel-install generates a fallback for one call (https://github.com/systemd/systemd/blob/v262.2/man/kernel-install.xml). `kernel-install add` refuses `--root=`/`--image=`, so it runs in a chroot (`src/kernel-install/kernel-install.c`, same tag). Plugins run in sorted order from `/etc/kernel/install.d` then `/usr/lib/kernel/install.d` as `<plugin> add KVER ENTRY_DIR KERNEL_IMAGE [INITRD…]` or `<plugin> remove KVER ENTRY_DIR`, with `KERNEL_INSTALL_BOOT_ROOT`, `KERNEL_INSTALL_LAYOUT`, `KERNEL_INSTALL_STAGING_AREA` and others set.
- **Fedora 45's plugins:** `systemd-udev`: `50-depmod`, `90-loaderentry`, `90-uki-copy`; `dracut`: `50-dracut`; `grub2-common`: `20-grub`, `95-set-boot-entry`, `99-grub-mkconfig`; `grubby`: `10-devicetree`, `95-kernel-hooks`; `dracut-config-rescue`: `51-dracut-rescue` (mdapi f45 file lists). Fedora's `50-dracut.install` writes `/boot/initramfs-<KVER>.img` when the layout is neither `bls` nor `uki` and `ENTRY_DIR` does not exist, removes it on `remove`, and builds nothing when initrds are passed as arguments (https://src.fedoraproject.org/rpms/dracut/blob/f45/f/dracut.spec, patch `0001-revert-fix-install.d-…`; https://github.com/dracut-ng/dracut/blob/111/install.d/50-dracut.install). No rescue image without `dracut-config-rescue`, which nothing in our image requires. `20-grub.install` copies the kernel to `/boot`, writes `/boot/loader/entries/` and calls `grub2-editenv` (https://src.fedoraproject.org/rpms/grub2/blob/f45/f/20-grub.install). `/etc/kernel/cmdline` is read by `20-grub`, `50-dracut` and `90-loaderentry`; without it they use `/proc/cmdline`, which in a chroot is the live ISO's.
- **Fedora's dracut defaults:** `hostonly="yes"`, `hostonly_cmdline="no"`, `early_microcode="yes"` (https://github.com/dracut-ng/dracut/blob/111/dracut.conf.d/fedora/01-dist.conf). Its `btrfs` module is included in hostonly mode when the host's root is btrfs, which in a chroot comes from the chroot's view of `/proc/self/mountinfo`.
- **Kernel RPM scriptlets:** `kernel-core`'s `%posttrans` runs `/bin/kernel-install add <KVERREL> /lib/modules/<KVERREL>/vmlinuz || exit 0` and copies `symvers.xz` to `/boot/symvers-<KVERREL>.xz`; `%preun` runs `kernel-install remove <KVERREL> || exit 0` (https://src.fedoraproject.org/rpms/kernel/blob/f45/f/kernel.spec near line 4237). A failing plugin does not fail dnf, so only a test catches it. dnf5 keeps 3 kernels (`installonly_limit`).
- **No arch-chroot:** Fedora 45's `arch-install-scripts-31-4.fc45` requires `pacman` and `archlinux-keyring` (mdapi). arch-chroot mounts proc, sysfs, efivarfs, devtmpfs, devpts, a tmpfs `/dev/shm`, a non-recursive bind of `/run` and a tmpfs `/tmp` (https://gitlab.archlinux.org/archlinux/arch-install-scripts/-/blob/v32/common). A non-recursive bind of `/run` does not carry the target's own mount under `/run/stackific-installer/target` into the chroot.
- **dnf5 offline removal:** `dnf5 --installroot=<dir> -y remove <pkgs>` loads only the system repo; `clean_requirements_on_remove` (default true) also removes packages installed only as dependencies; config comes from inside the installroot (https://github.com/rpm-software-management/dnf5/blob/5.4.6.0/dnf5/commands/remove/remove.cpp#L111-L113, `doc/dnf5.conf.5.rst`, `doc/misc/installroot.7.rst`).
- **GNOME defaults:** a package ships `/usr/share/glib-2.0/schemas/<nn>_<name>.gschema.override`; Fedora's glib2 recompiles schemas from a file trigger, so no scriptlet is needed (https://src.fedoraproject.org/rpms/glib2/blob/f45/f/glib2.spec). The higher number wins (https://gitlab.gnome.org/GNOME/glib/-/blob/2.90.0/docs/reference/gio/glib-compile-schemas.rst L41-51). Fedora's own wallpaper override sets `[org.gnome.desktop.background] picture-uri`, `picture-uri-dark` and `[org.gnome.desktop.screensaver] picture-uri` (https://src.fedoraproject.org/rpms/desktop-backgrounds/blob/f45/f/desktop-backgrounds.spec L170-186; not in our image). `org.gnome.shell favorite-apps` defaults (Fedora's gnome-shell patch) to Firefox, Calendar, Nautilus, Software, Text Editor and Calculator; an override replaces the whole list (https://gitlab.gnome.org/GNOME/gnome-shell/-/blob/51.0/data/meson.build L121-124; https://src.fedoraproject.org/rpms/gnome-shell/blob/f45/f/gnome-shell-favourite-apps-firefox.patch).
- **The live ISO's boot menu:** kiwi writes the ISO's `grub.cfg` from a Python template; `<bootloader grub_template="<file>">` replaces it, and `<type editbootconfig="<script>">` runs a script outside the image root after `grub.cfg` is written, with `iso:<media dir>` as `$1`. kiwi's live entry is `linux ($$root)${bootpath}/${kernel_file} $${extra_cmdline} $${isoboot} ${boot_options}` (kiwi v11.1.1 `doc/source/image_description/elements.rst` L1427-1475; `kiwi/bootloader/template/grub2.py` L149-156; `kiwi/builder/live.py` L185-191). kiwi's own "Install" entry is for OEM images and does not apply.
- `run0` is `/usr/bin/run0` in Fedora 45's systemd; gnome-shell requires polkit and is the polkit agent in GNOME; Noctalia's agent is on in our defaults (AGENTS.md).

## Design
- **`Fedora` behind `Base`** (`installer/src/base.rs`), picked when `ID_LIKE` has `fedora`:
  - `live_root` `/run/rootfsbase`, `live_medium` `/run/initramfs/live`.
  - `live_state`: `dnf5 --installroot=<target> -y remove stackific-installer grub2-efi-x64 grub2-efi-x64-cdboot grub2-efi-x64-modules`, so the installed system keeps no installer, no launcher and no GRUB (with `clean_requirements_on_remove`, `grub2-common`, `grub2-tools*` and `grubby` go too where only these needed them; the build checks the manifest and names any that stay). Run it before `initramfs`, so GRUB's kernel-install plugins never run on the target.
  - `initramfs`: write `<target>/etc/kernel/cmdline` (`root=UUID=<uuid> rootflags=subvol=/@ rw`, the same text `limine_conf` uses, from one shared function in `boot.rs`); mount `proc`, `sysfs`, `efivarfs` (when the live system has it), a `devtmpfs` or bind of `/dev` with `devpts`, and a non-recursive bind of `/run` into the target, as arch-chroot does; then `chroot <target> kernel-install add <KVER> /usr/lib/modules/<KVER>/vmlinuz` for each folder under the target's `/usr/lib/modules/`. The installer's final `umount --recursive` removes these mounts. The trait's signature changes as needed to pass the root UUID; Arch's commands stay the same.
  - `limine.conf`: written by the plugin, not by the installer. `Base` says whether the installer writes it (Arch: the static entry from `kernel_files`; Fedora: nothing, the plugin did). The program copies and the firmware entry stay shared and unchanged.
  - SELinux: after every write to the target and before the firmware entry, `setfiles -r <target> -e <target>/boot <target>/etc/selinux/targeted/contexts/files/file_contexts <target>`, so files the installer created (the user's home, `/etc/fstab`, greetd's config, the MangoWM config, `/etc/kernel/cmdline`) get the policy's labels. `/boot` is FAT and holds no labels. Arch runs nothing here.
- **`stackific-boot` RPM** (`fedora/packages/stackific-boot/`, `BuildArch: noarch`, `Requires: limine efibootmgr dracut systemd-udev`):
  - `/usr/lib/kernel/install.conf.d/50-stackific.conf`: `layout=other`, `BOOT_ROOT=/boot`.
  - `/usr/lib/kernel/install.d/90-stackific-limine.install` (shell, `set -euo pipefail`, shellcheck clean): does nothing (exit 0) while `/etc/kernel/cmdline` or `$KERNEL_INSTALL_BOOT_ROOT/EFI/limine/` is missing (the live image and its build). On `add KVER _ KERNEL [INITRD…]`: `install -m 0644` the kernel to `$BOOT/vmlinuz-KVER`; if dracut left no `$BOOT/initramfs-KVER.img`, copy the first passed initrd there. On `remove KVER`: delete `$BOOT/vmlinuz-KVER` and `$BOOT/symvers-KVER.xz` (dracut removes the initramfs). Then, on both, rewrite `$BOOT/limine.conf` atomically (write a temporary file on the ESP, then `mv`) from every `vmlinuz-*` on the ESP that has its `initramfs-*.img`, minus the removed one, sorted with `sort -rV`:

    ```text
    timeout: 3
    interface_branding: Stackific OS

    /Stackific OS
        protocol: linux
        path: boot():/vmlinuz-7.2.15-300.fc45.x86_64
        module_path: boot():/initramfs-7.2.15-300.fc45.x86_64.img
        cmdline: root=UUID=<uuid> rootflags=subvol=/@ rw

    /Stackific OS (7.2.14-300.fc45.x86_64)
        protocol: linux
        path: boot():/vmlinuz-7.2.14-300.fc45.x86_64
        module_path: boot():/initramfs-7.2.14-300.fc45.x86_64.img
        cmdline: root=UUID=<uuid> rootflags=subvol=/@ rw
    ```

    `Stackific OS` is os-release's `NAME`; the command line is `/etc/kernel/cmdline`'s. The first entry's header and fields are byte-identical to `boot::limine_conf`'s output for the same kernel, which a unit test or the install test compares. Why glue: no Fedora or Terra package writes Limine entries, and Limine reads no BLS entries.
  - `%triggerin -- limine`: when `/boot/EFI/limine/` exists, copy `/usr/share/limine/BOOTX64.EFI` over `/boot/EFI/limine/BOOTX64.EFI` and `/boot/EFI/BOOT/BOOTX64.EFI` (the counterpart of Arch's pacman hook).
- **`stackific-installer` RPM** (`fedora/packages/stackific-installer/stackific-installer.spec`, `ExclusiveArch: x86_64 aarch64`): the same files at the same paths as the Arch package (program, launcher rendered with `envsubst '$NAME $ID'`, both units). `BuildRequires: cargo rust gettext-envsubst systemd-rpm-macros`; `Requires: btrfs-progs dosfstools e2fsprogs efibootmgr foot kbd limine policycoreutils rsync shadow-utils systemd util-linux xkeyboard-config dnf5 stackific-boot stackific-release`. `%check` runs `cargo test --frozen`. The crate reaches mock as one tar, as for makepkg; the crates come either from mock with `--enable-network` and `cargo fetch --locked` in `%prep` (as the PKGBUILD's `prepare()`), or from a vendored tar; the build picks one, says which in `docs/fedora-iso.md`, and keeps every other spec's build offline.
- **`just fedora packages`:** also stages the files beside each spec (as `just arch packages` does since 013), packs the crate tar for the installer, and copies every binary RPM (`*.noarch.rpm` and `*.<arch>.rpm`, not the source RPMs) to the repo.
- **The image** (`fedora/iso/config.kiwi`): `dnf5` (both architectures); `stackific-installer` and `stackific-boot` with `arch="x86_64"` (aarch64 waits for task 018); `fedora/iso/terra-repo.sh` adds `limine` to `includepkgs`. If the manifest lacks `rpm` or `policycoreutils`, name them.
- **The boot menu:** the x86_64 ISO's GRUB menu has "Try Stackific OS (x86_64, UEFI)" (default, today's entry, retitled if needed) and "Install Stackific OS (x86_64, UEFI)", the same `linux` line plus `systemd.unit=stackific-installer.target`; through `editbootconfig` or `grub_template`, whichever is less code and boots in the test. The aarch64 ISO keeps one entry.
- **GNOME** (`stackific-desktop.spec`, Fedora only): `/usr/share/glib-2.0/schemas/20_stackific.gschema.override` with `[org.gnome.desktop.background] picture-uri` and `picture-uri-dark` and `[org.gnome.desktop.screensaver] picture-uri` set to `file:///usr/share/backgrounds/stackific/an-eruption-of-vesuvius-johan-christian-dahl.jpg`, and `[org.gnome.shell] favorite-apps=['stackific-installer.desktop', 'org.gnome.Nautilus.desktop', 'org.gnome.Ptyxis.desktop']` (GNOME skips an entry whose app is missing, as on installed systems). `Requires: gsettings-desktop-schemas` only if mock's file check needs it.

- `just fedora test-install` passes:
  - the ISO's `grub.cfg` has "Try Stackific OS (x86_64, UEFI)" as default and "Install Stackific OS (x86_64, UEFI)" with `systemd.unit=stackific-installer.target`;
  - the first boot passes every check `install.sh` runs on Arch (console path, refused erase, erase, Windows-like table with the BitLocker refusal, free-space install), with Fedora's equivalents for the base-specific ones;
  - the second boot, from the disk alone: OVMF starts `Boot#### "Stackific OS"`; `limine.png` shows Limine's menu with "Stackific OS" first; the system reaches `running`, `getenforce` prints `Enforcing`, the login screen shows; `/proc/cmdline` has `root=UUID=<UUID of />`, `rootflags=subvol=/@`, `rw`; `findmnt` shows `/` btrfs `subvol=/@` and `/boot` vfat; `btrfs subvolume get-default /` prints `ID 5 (FS_TREE)`;
